# GridOpsAgent 系统演示流程

本文档用于汇报、答辩或本地演示时稳定复现系统核心能力。

## 1. 启动前检查

在 Docker Desktop 中启动必需容器：

| 容器 | 状态 | 说明 |
| --- | --- | --- |
| `mysql-gridops` | Running | 保存会话、知识库文档、切片、Trace 与工具日志。 |
| `milvus-standalone` | Running / healthy | RAG 向量库，端口 `19530`。 |
| `milvus-minio` | Running / healthy | Milvus 对象存储依赖。 |
| `milvus-etcd` | Running / healthy | Milvus 元数据依赖。 |

可选：

- `milvus-attu`：Milvus Web 管理界面，不影响主应用。
- `redis-gridops`：预留缓存组件，当前核心链路不强依赖。

## 2. 启动本地服务

在项目根目录执行：

```powershell
cd E:\code\电网agent项目\GridOpsAgent-main
$env:DEEPSEEK_API_KEY="你的 DeepSeek API Key"
.\scripts\start-gridops.ps1 -SkipDocker
```

检查状态：

```powershell
.\scripts\status-gridops.ps1
```

理想状态：

```text
Main app          9900   True   HTTP 200
MCP server        9901   True
BGE-M3 embedding  9910   True   HTTP 200
MySQL             3307   True
Milvus            19530  True
```

如果知识库运维页显示“向量库异常 / 当前使用内存向量库”，通常是主应用早于 Milvus 启动。重新执行：

```powershell
.\scripts\start-gridops.ps1 -SkipDocker
```

脚本会自动重启主应用并切回 Milvus。

## 3. 打开系统

浏览器访问：

```text
http://localhost:9900/
```

推荐演示顺序：

1. 知识库运维
2. 执行前检查台
3. 知识拓扑
4. 运行诊断控制台

## 4. 知识库运维演示

进入“知识库运维”：

1. 查看 RAG 健康面板。
2. 确认 MySQL、Milvus、Embedding API 为正常。
3. 点击 RAG 自检。
4. 展示结果：`RAG 自检：通过`。

说明口径：

- 文档元数据和切片写入 MySQL。
- 向量写入 Milvus。
- Embedding 使用本地 BGE-M3，不消耗 DeepSeek token。
- 如果 Milvus 不可用，系统会降级为内存向量库，并明确提示重启丢失。

## 5. 执行前检查台演示

输入：

```text
主变油温异常诊断，请查询状态、告警历史并给出处置建议
```

点击“生成检查”。

展示要点：

- BGE-M3 语义匹配 + 关键词校验命中流程模板。
- 页面展示目标 Graph、计划步骤、样例数据可用性、RAG 运行时检索和半真实推演步骤。
- 推荐能力来自模板和知识节点，但只作为执行链路检查的辅助信息。
- 关联图谱展示当前任务相关的流程、工具和知识实体。

说明口径：

- 执行前检查台用于确认这条任务后续会怎样进入 Graph。
- 真正工具调用、RAG 检索、多 Agent Graph 执行发生在“运行诊断控制台”。

## 6. 运行诊断控制台演示

输入：

```text
主变TR-110KV-001油温86C超过80C阈值，请诊断
```

推荐点击“运行诊断”。

展示要点：

- Agent 执行轨迹显示每个节点状态、耗时和累计耗时。
- 当前节点运行时显示动态状态。
- 执行过程默认折叠，可展开查看溯源。
- 工具调用结果显示中文工具名、状态、失败原因和摘要。
- 最终回答以 Markdown 排版展示诊断目标、核查结果、初步判断、建议处置和数据缺口。

当前 mock 覆盖的高频证据：

| 场景 | 覆盖内容 |
| --- | --- |
| 主变油温异常 | 油温 `86℃`、阈值 `80℃`、油温越限 `+6℃`。 |
| 冷却器异常 | 冷却器状态异常、风扇 2 启动失败、风扇 3 备用未投入。 |
| 负荷异常 | 负荷率 `92%`，高于 `90%` 关注阈值。 |
| 历史告警 | 油温异常、冷却器控制回路异常、温控器动作不灵敏。 |
| 运行日志 | 冷却器启动失败、温控器切换失败、油温越限。 |
| 缺陷工单 | 冷却器控制回路、温控器、油温偏高重复缺陷。 |

## 7. 溯源查看演示

在执行轨迹中展开：

- `上下文装载`：查看命中流程模板、候选知识节点。
- `计划编排`：查看生成的诊断计划。
- `工具执行`：查看每个工具调用结果、失败原因、耗时。
- `证据校验`：查看证据覆盖情况。
- `处置建议`：查看最终报告生成前的归纳过程。

失败原因解释：

| 展示文案 | 含义 |
| --- | --- |
| 数据源未接入 | 真实 PMS/SCADA/EMS/工单系统未接入。 |
| 演示数据缺失 | 当前 mock 数据未覆盖查询条件。 |
| 参数不匹配 | Planner 生成的工具参数缺少有效设备编号等。 |
| 接口异常 | 工具服务或调用链路异常。 |
| 返回结构不合法 | 工具返回缺少期望字段。 |
| 工具未注册 | 计划里出现当前系统不可执行的工具名。 |

## 8. 知识拓扑演示

进入“知识拓扑”：

1. 展示完整知识组织图谱。
2. 使用滚轮缩放、拖拽平移。
3. 点击节点查看详情。
4. 切换任务子图，展示与当前任务相关的局部图谱。

说明口径：

- 知识拓扑来自 nari 原型迁移后的内置 JSON 资源。
- 图谱用于流程匹配、Planner 上下文增强和可解释展示。

## 9. 推荐演示话术

可以按下面顺序讲：

1. 系统不是单一聊天框，而是显式 Graph + 多 Agent 编排。
2. 任务编排台先做流程模板匹配，不直接执行工具。
3. 运行诊断控制台真正执行 Router、Planner、ToolAgent、Evidence Validator、Replanner、Safety Review。
4. RAG 使用本地 BGE-M3 和 Milvus，DeepSeek 主要用于规划、诊断和总结。
5. 当前 EMS/DTS/SCADA 是 mock/estimate，工具返回和 README 中都明确标注边界。
6. 执行轨迹可折叠溯源，能看到每一步依据、耗时和失败原因。

## 10. 停止服务

仅停止本地服务：

```powershell
.\scripts\stop-gridops.ps1
```

连 Docker 基础设施一起停止：

```powershell
.\scripts\stop-gridops.ps1 -WithDocker
```
